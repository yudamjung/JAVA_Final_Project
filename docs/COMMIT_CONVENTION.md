# 커밋 규칙

커밋 제목은 변경 내용을 짧고 분명하게 설명합니다. 제목은 명령형으로 작성하고, 한 커밋에는 하나의 논리적 변경만 담습니다.

## 제목 형식

`<type>: <변경 내용>`

예시: `feat: 로그인 기능 추가`

## 유형

- `feat`: 사용자 기능 추가
- `fix`: 버그 수정
- `docs`: 문서 작성 또는 수정
- `refactor`: 동작 변경 없는 코드 구조 개선
- `test`: 테스트 추가 또는 수정
- `build`: 빌드 및 의존성 설정 변경
- `chore`: 기타 유지보수 작업

## 작성 기준

- 제목은 한국어 또는 영어로 일관되게 작성하고, 마침표는 붙이지 않습니다.
- 제목은 무엇을 변경했는지 나타내며, 불필요한 세부 구현은 넣지 않습니다.
- 본문에는 변경 이유와 영향 범위를 적습니다. 단순한 변경이면 생략할 수 있습니다.
- 관련 이슈가 있으면 본문에 `Refs: #번호` 또는 `Closes: #번호`로 연결합니다.
- 커밋 전에 변경 파일을 확인하고, 비밀 정보나 빌드 산출물이 포함되지 않았는지 확인합니다.

## 예시

```text
feat: 회원 가입 입력 검증 추가

이메일 형식과 비밀번호 길이를 확인해 잘못된 가입 요청을 막습니다.
Refs: #12
```
